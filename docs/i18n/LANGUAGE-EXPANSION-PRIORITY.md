# Flixo — Language Expansion Priority

## Production rule

Every language is treated as a complete local market experience. A language cannot be activated in `LOCALES` or exposed as a finished SEO locale until its dictionary, terminology profile, native UX copy, SEO metadata, tool names/taglines, localized routes, hreflang coverage, and automated validation are complete.

No language may use English as a production fallback.

## Next expansion candidate

### Hungarian (`hu`)

Hungarian is the next candidate for a future full localization pass. W3Techs' current web-language measurements place Hungarian among the more common web content languages beyond the existing Flixo set, making it a reasonable incremental European expansion. It remains **planned**, not production, until the complete localization contract is satisfied.

## Selection rule for future additions

A new language is added only when at least one of these is true:

1. It has meaningful web/content usage and an identifiable software/online-tools audience.
2. It gives Flixo access to a geographically meaningful market that is not well covered by an existing language.
3. Search-demand or first-party Flixo analytics demonstrate meaningful unmet demand.

When a new language is selected, implementation happens language-by-language:

1. Native market terminology research.
2. Language glossary and style profile.
3. Complete dictionary with no inheritance from English.
4. Tool names, taglines, descriptions and UI copy.
5. Local SEO titles, descriptions, FAQs and search-intent phrases.
6. Localized routes, canonical and hreflang validation.
7. RTL/LTR and accessibility review where applicable.
8. Localization-agent and CI validation.
9. Only then production activation.

## Quality principle

More languages are valuable only when they are real local experiences. A smaller set of complete languages is preferable to a larger set of pages containing untranslated or literal text.

Reference data source: W3Techs content-language measurements, reviewed August 2026.
